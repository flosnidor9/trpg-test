# TRPG 성향 테스트

함께 플레이할 때 편한 RP 호흡과 세션 운영 조건을 읽고 비교하는 브라우저 앱입니다. 개인 결과는 그래프와 핵심 방향으로, n명 비교는 겹친 레이더와 운영 응답표로 제공합니다.

## 실행

게시 주소: https://flosnidor9.github.io/trpg-test/

GitHub Pages는 `main` 브랜치의 루트 디렉터리를 게시합니다. `main`에 변경 사항을 푸시하면 자동으로 반영됩니다. `.nojekyll`로 Jekyll 처리를 생략하고 HTML·CSS·JavaScript를 그대로 제공합니다.

빌드나 서버 API는 필요하지 않습니다. 이 디렉터리에서 정적 서버를 실행하세요.

```sh
python3 -m http.server 8000
```

브라우저에서 http://localhost:8000 을 엽니다.

## 현재 구현

- 시작 조건 2개, RP 6개, 운영 26개, 경계 2개의 **총 36개 문항 묶음**. 타이핑 시간은 RP에 포함하며, 세부 활동·소재는 묶음 안에서 각각 답합니다.
- 답변하면 다음 문항이 아래로 이어지는 스크롤 진행, 위로 스크롤해 이전 답변 수정, 키보드 선택과 로컬 중간 저장. 필수 추가 입력은 작성 완료 후 진행하며 마지막에는 결과 보기.
- 스크롤 중에도 상단에 유지되는 초기화 버튼으로 진행 중인 답변을 지우고 처음부터 다시 시작.
- 개인 결과는 RP 템포·표현 분량·장면 호흡·RP 시작·조율 시점의 5축 레이더를 보여줍니다. 파티 비교 레이더는 RP 흐름·표현과 장면·세션 호흡·사담·롤방 준비·일정 준비의 6축으로 여러 응답을 대략 묶습니다. 최저 응답도 가장 안쪽 눈금에 표시해 면적을 유지합니다. 실제 응답과 경계·플랫폼처럼 한 줄의 높낮이로 나타낼 수 없는 응답은 표에서 확인합니다.
- 개인 결과에는 레이더와 다섯 축의 핵심 방향만 표시하고, 상세 응답은 JSON 미리보기와 파티 비교에서 확인합니다.
- 개인 결과 상단에 관련 응답을 묶은 세션 취향 카드를 최대 5장 표시합니다. RP·대화·휴식과 참여·연출·운영의 13개 묶음에서 두 가지 이상의 선호가 함께 나타날 때 카드를 생성하고, 일치한 응답의 강도 합계와 개수로 순서를 정합니다. 설명에는 실제 일치한 선호만 담으며 경계와 자유 입력은 판정에 사용하지 않습니다. 개인 성향 지도와 파티 비교는 같은 6개 축과 최소 면적을 사용합니다.
- 휴식 간격과 길이, 참여 지원, 활동별 딴짓 허용, 사담 비중·위치.
- 외부 구인 범위·참가 확정·빈자리 대체 합류 시점, 당일 및 반복 취소 후 재조율·변경 연락·최소 인원·일정 후보와 확정.
- 세션카드·BGM·맵시트·포트레이트 각각의 선호, 최소 필요, GM 제공 가능 수준.
- 메타발언 종류, 캐릭터 개그와 플레이어 농담, 대사·지문·사담별 초성 사용.
- 선호 플랫폼·연락 채널·타이핑 시간과 예시 칩·직접 입력을 지원하는 불호 요소 문항.
- 소재와 캐릭터 행위별 경계. 화면에서는 모두 한국어로 표시.
- JSON 내보내기 전 이름 설정 및 미리보기. 경계와 자유 입력은 기본 포함하며 이전 결과의 비공개 세부 항목은 항상 제외.
- 여러 결과 JSON·픽셀 워터마크 이미지(PNG·JPEG·WebP)의 파일 선택·드래그 앤 드롭, JSON 붙여넣기·이 기기 결과 가져오기.
- 최대 6명의 레이더 선택과 표시 이름 변경·참가자 제거. 레이더 축 이름에서 방향을 마우스와 키보드로 확인할 수 있습니다.
- 개인 결과와 파티 비교에서 원본 PNG와 파티 비교용 PNG의 미리보기·저장을 따로 제공합니다. 원본은 3840px 너비의 2배 해상도로 직접 그려 워터마크 없이 선명하게 공유할 수 있고, 파티 비교용은 공개 결과 데이터를 픽셀 워터마크에 담아 다시 불러올 수 있습니다. 왼쪽에는 성향 지도와 실제 응답 설명, 오른쪽에는 그림이 있는 세션 취향 카드를 담습니다. 파티 PNG의 지도와 공통 카드는 현재 선택한 참가자 기준이며, 플레이 스타일 유사도와 텍스트 설명은 전체 참가자 기준입니다. 이미지 생성과 저장은 브라우저 안에서 처리합니다.
- 파티 지도 아래에 함께 적용할 조건과 같은 기준으로 요약한 텍스트 응답표를 제공하며, 공통 취향은 그림 카드와 모두에게 확인된 선호 설명으로 표시합니다.
- 파티 운영표는 GM·PL 역할을 따로 표시하고, 서로 다른 응답 중 적용할 수 있는 가장 제한적인 조건을 먼저 보여줍니다. 순서를 정할 수 없는 선택지는 별도 조율로 남깁니다. 참가자 응답이 다를 때만 굵게 표시하며, 마우스오버나 키보드 포커스로 각자의 답을 확인할 수 있습니다.
- 선호 플랫폼은 응답한 참가자의 최다 득표로 표시하고, 동률은 조율 대상으로 표시합니다. 플랫폼을 밝히지 않은 참가자는 득표에서 제외하고 미확인 인원으로 표시합니다.
- 롤방 준비 항목은 목록형 표에서 여러 GM 중 가장 낮은 제공 가능 수준만 표시합니다. 포트레이트는 GM 제공 범위 대신 참가자 중 가장 낮은 선호 수준을 표시합니다. 각 행에 마우스를 올리거나 키보드로 초점을 맞추면 참가자별 선호와 최소 필요 수준을 볼 수 있으며, 터치로도 열 수 있습니다. 경계 확인은 문항 묶음을 소제목으로 나누고, 각 행에는 세부 경계 이름만 표시합니다.

## 결과 해석

좌표는 선호 방향을 표시하는 프로토타입 규칙입니다. 검증된 심리검사, 백분위, 실력 점수, 궁합 퍼센트가 아닙니다. 각 축의 높고 낮음에 우열이 없습니다.

RP 응답은 0–100 좌표로 표시합니다. 지문 분량은 단문·중문·장문 3단계, 나머지 축은 5단계입니다. 미응답 축은 좌표에서 제외합니다.

세션 호흡 좌표는 세션 길이·휴식 간격·휴식 길이를 묶어 표시합니다. ‘회차마다 조율’과 ‘필요할 때 쉬기’는 표시용 중간값(50)으로 반영합니다. 이는 고정된 시간 선호를 뜻하지 않으며, 실제 조율에는 원래 응답을 사용합니다.

플레이 스타일 유사도는 불러온 전체 참가자의 정형 응답을 **RP·참여와 휴식·교류와 소통·구인과 합류·일정·롤방 준비·플랫폼과 연락·경계**의 8개 고정 영역으로 묶습니다. 영역 비중은 각각 12.5%입니다. 각 영역 안에서는 고정 문항의 비중을 같게, 행렬 안에서는 세부 행의 비중을 같게 적용합니다. 역할은 참가자 배정 정보로 표에 유지하며 성향 점수에는 넣지 않습니다. 레이더 표시 선택은 전체 유사도에 영향을 주지 않습니다.

측정 방식은 저장용 선택지 번호에서 추론하지 않고 문항별로 지정합니다. RP 5개 축·휴식 길이·사담 비중은 명시한 순서 좌표, 일정 확정은 실제 날짜 범위(3–30일)로 환산해 `100 − 2 × 전체 평균에 대한 평균 절대편차`를 계산합니다. 순서형 좌표의 같은 간격은 초기 설계 가정이며 검증된 측정 간격이 아닙니다. 유동 응답이 섞인 시간·일정, 서로 다른 기능을 나타내는 준비 수준, 겹치는 타이핑 구간 등 나머지 선택지는 범주형으로 비교합니다.

범주형은 전체 응답 비율의 집중도 `C = Σ p²`를 사용합니다. 고정 선택지 수가 K인 항목은 `100 × (C − 1/K) / (1 − 1/K)`로 정규화합니다. 같은 응답은 100, 모든 선택지에 균등하게 나뉘면 0입니다. 인원수나 동일 응답 분포의 복제에 따라 점수가 변하지 않으며 최다 응답 이외의 분포도 반영합니다. 플랫폼·연락 채널은 사용자 지정 이름까지 하나의 식별값으로 비교합니다. 가능한 이름의 범주 수가 제한되지 않으므로 기준값 0을 사용해 `100 × C`로 표시합니다. 이름이 다르다는 사실 외의 거리는 추정하지 않습니다. 이들 항목에서는 서로 다른 두 이름이 50점이며 다른 모든 응답을 0점으로 처리하는 지표가 아닙니다. 이름은 기본 응답에 한 번만 반영합니다.

불호 요소는 기존 예시 칩의 5개 고정 태그만 구조화해 비교합니다. 태그의 순서·중복·공백은 무시합니다. 자유 문장으로 미선택 태그나 의미 유사성을 추측하지 않으며, 자유 문장과 메모·가능 시간대·필수 인물은 원문 응답표에 유지합니다. 명시적으로 불호가 없다는 빈 응답은 공유에도 보존하며 미공유와 구분합니다. 최소 필요 수준·GM 제공 가능 수준·최소 인원·진지한 장면 조건은 적용 대상 참가자끼리 별도 비교하고 전체 취향 점수에 합산하지 않습니다. GM과 PL이 섞여 있어도 GM끼리 제공 수준을 비교할 수 있습니다.

미응답·비공개를 동일 응답으로 취급하거나 중간값으로 채우지 않습니다. 각 영역의 문항별 비교 범위 평균이 80% 이상일 때만 전체 결과를 표시합니다. **80%는 초기 제품 표시 정책이며 통계적 검증 기준이 아닙니다.** 모든 항목이 확인되면 마지막에 정수로 반올림한 단일 퍼센트를 표시합니다. 일부 항목이 미확인일 때는 해당 항목의 점수를 0–100으로 열어 두어 계산한 가능한 전체 점수 범위를 표시합니다. 아래 경계값은 내림, 위 경계값은 올림하며 이 범위는 신뢰구간이 아닙니다. 비교 범위가 부족하면 전체 점수는 보류하고 확인한 영역별 응답을 보여줍니다.

비교 화면의 ‘영역별 유사도’에서 8개 영역의 점수를 확인할 수 있습니다. 부분 응답의 영역 점수는 ‘일부’로 표시합니다. PNG에도 8개 영역의 점수를 담습니다. 전체 값은 서로 다른 비교 지표를 고정 가중치로 묶은 설계 지표이며 실제 만족도나 궁합을 예측하는 검증된 점수가 아닙니다. 경계를 포함해 비교하지만 기존 제외·사전협의 규칙은 점수로 상쇄하지 않습니다.

휴식 간격, 일정의 준비 기간, 콘텐츠 경계는 취향 평균으로 상쇄하지 않습니다. 운영 제안은 합의 완료가 아니며 실제 수용 여부를 함께 확인해야 합니다.

## 데이터와 버전

파티 비교용 PNG의 비교 데이터는 v2 DCT 픽셀 워터마크로 저장합니다. canonical 해상도, sync 패턴, 7회 반복과 confidence voting으로 축소·재인코딩 내성을 높이고 기존 v1 원본 PNG 읽기를 유지합니다. iTXt 등 metadata를 사용하지 않습니다. 공개 API, 데이터 포맷, 용량, 강도·반복 수 설정과 제한은 [WATERMARK.md](WATERMARK.md)를 참고하세요. [watermark-demo.html](watermark-demo.html)에서 이미지와 임의 JSON을 직접 삽입·복구할 수 있습니다. 기존 iTXt 전용 PNG는 JSON을 가져와 새 PNG로 다시 저장해야 합니다.

저장 형식은 `schemaVersion: "3.0"`, 문항 버전은 `rp-2026-10-v7`입니다. 문항별 `responses`를 보존하고, 가져올 때 선택지·범위·문자열·추가 조건을 검증한 뒤 레이더와 맥락을 다시 계산합니다. v6의 응답은 그대로 유지하며 타이핑 시간 문항 위치만 RP 문항 뒤로 옮깁니다.

이전 `rp-2026-10-v1`~`v5` 결과와 진행 중인 답변은 남은 문항으로 이어서 사용합니다. 의미나 선택지가 달라진 응답은 제외하고 다시 답할 수 있습니다.

- `trpg-playstyle-profile`: 현재 개인 결과.
- `trpg-rp-draft-v3`: 진행 중인 답변.
- `trpg-playstyle-profile-previous`: 새 결과를 저장하기 전의 이전 결과.

2.0의 8축은 새 5축과 의미가 달라 자동 변환하거나 같은 비교에 넣지 않습니다. 기존 결과 화면에서 이전 좌표를 열람하고 원본을 저장할 수 있습니다.

결과와 비교 데이터는 브라우저 안에서 처리합니다. 응답·비교 정보를 자동 업로드하거나 외부 AI에 전송하지 않습니다. 해설은 사전에 작성한 문안과 명시적인 응답 조건으로 조합합니다. 비교 화면의 참가자 목록은 화면을 열어둔 동안만 유지됩니다.

캐릭터 전개·소재별 허용 범위와 직접 적은 조건·일정·불호 요소·메모는 내보내기에 기본 포함합니다. 이전 결과의 비공개 항목은 제외하며, 공유되지 않은 경계는 비교에서 허용이 아닌 미확인입니다. 레이더 우측 공통 카드는 선택한 참가자 모두가 가진 카드만 표시합니다.

- `app.js`: 검증·계산·공유 필터·그래프·개인 결과.
- `cards.js`: 기존 답변을 세션 취향 카드에 연결하고 대표 카드 순서를 정하는 규칙.
- `test-flow.js`: 질문 진행과 로컬 중간 저장.
- `comparison.js`: 겹친 레이더·운영표·참가자별 조율 제안.
- `style.css`, `app.css`: 랜딩 및 새 앱 화면 스타일.
- `index.html`, `test.html`, `result.html`, `compare.html`: 화면 진입점.

설계 설명은 [문항 설계안](RP_QUESTIONNAIRE_PLAN.md), [결과 해설 설계안](RESULT_NARRATIVE_PLAN.md)을 참고하세요. 관계 서사·공동 창작 등 확장 항목과 통계적 척도 검증은 설계 검토 대상으로 남아 있습니다.

## 검증

계산과 공유·경계 규칙:

```sh
node --test tests/profile.test.cjs tests/png-metadata.test.cjs
```

브라우저 흐름과 WCAG AA 관련 자동 점검은 Playwright와 axe-core를 사용합니다. 앱 자체에는 이 의존성이 필요하지 않습니다. 테스트 도구를 임시 디렉터리에 설치해 실행할 수 있습니다.

```sh
TRPG_CHECK_TOOLS=$(mktemp -d)
npm install --prefix "$TRPG_CHECK_TOOLS" playwright @axe-core/playwright --no-audit --no-fund
TRPG_PLAYWRIGHT_MODULE="$TRPG_CHECK_TOOLS/node_modules/playwright" TRPG_AXE_MODULE="$TRPG_CHECK_TOOLS/node_modules/@axe-core/playwright" node tests/browser-check.cjs
```

macOS의 설치된 Chrome을 기본 사용합니다. 다른 환경에서는 Playwright 브라우저를 설치하거나 `TRPG_BROWSER`에 실행 파일 경로를 지정하세요. 스크린샷은 테스트가 만든 임시 디렉터리에 저장하고 경로를 출력합니다.

브라우저 점검 범위: 처음부터 끝까지 응답, 중간 저장과 수정, 키보드 선택, 개인 결과, 1명·2명·다수 비교, 잘못된 JSON, 공유 필터, 이전 결과, 모바일 가로 넘침, 모션 감소. 자동 접근성 검사는 수동 점검을 대체하지 않습니다.
