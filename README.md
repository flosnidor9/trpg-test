# TRPG 성향 테스트

TRPG를 함께 즐길 때의 **플레이 취향**과 **세션 운영 방식**을 확인하는 테스트입니다. 결과는 공유 가능한 JSON으로 내보내며, 2명 이상(`n`명)의 결과를 불러와 레이더 차트에 겹쳐 보고 팀 적합도를 확인합니다.

> 이 테스트의 점수는 사람의 좋고 나쁨이나 TRPG 실력을 판단하지 않습니다. 서로 다른 취향을 미리 발견하고, 세션 0 전에 조율할 대화를 만드는 것이 목적입니다.

## 참고한 성향표와 분류

| 범주 | 참고 성향표의 항목 | 테스트에서의 처리 |
| --- | --- | --- |
| 세션 환경 | 온라인/오프라인, 보이스/텍스트, 1:1/다인, 플랫폼, GM/PL | 필수 조건 또는 선택형 프로필 |
| 운영·일정 | 가능 요일, 사전 조율 시점, 도착·휴식·연락·당일 취소 | 일정 매칭 및 운영 선호 |
| 표현·소통 | 단문/중문/장문, 대사·지문, 사담, 메타 발언, 초성, 딴짓 | 레이더 축과 세부 선호 |
| 플레이·서사 | RP, 전투, PVP, 협력/대립, 은닉, 레일로드, 정보 격차, 로맨스 | 레이더 축과 합의 항목 |
| 캐릭터·안전 | 캐릭터 취향, 노출/폭력 수위, 트리거, 묘사 가능 여부 | 점수화하지 않는 경계·동의 규칙 |

참고 성향표의 개인별 항목을 그대로 평가하거나 복제하지 않습니다. 특히 캐릭터 속성, 성적·폭력 콘텐츠, 트리거는 “잘 맞음”을 위한 가산점이 아니라 **명시적 동의가 필요한 경계**로 취급합니다.

## 테스트 모델

### 레이더 차트: 8개 성향 축

모든 축은 `0`~`100`이며, 높고 낮음에 우열은 없습니다. 결과 화면에는 축의 양 끝 설명을 함께 표시합니다.

| 키 | 축 | 0에 가까운 쪽 | 100에 가까운 쪽 |
| --- | --- | --- | --- |
| `pace` | 진행 속도 | 여유 있는 응답·긴 호흡 | 빠른 턴·즉각적인 반응 |
| `expression` | 표현 밀도 | 행동·핵심 위주의 간결한 표현 | 지문·감정·묘사가 풍부한 표현 |
| `immersion` | 인물 몰입 | 메타 대화와 규칙 대화도 편안함 | 캐릭터 시점과 분위기 유지 중시 |
| `structure` | 진행 구조 | 자유 탐색·즉흥 전개 선호 | 목표·장면·진행 틀이 분명한 전개 선호 |
| `cooperation` | 협력 지향 | 개인 서사·경쟁도 즐김 | 파티 협력과 공동 목표 중시 |
| `conflict` | 갈등 강도 | 안전한 관계·낮은 대립 선호 | 캐릭터 간 대립·PVP 가능 |
| `relationship` | 관계 서사 | 사건·탐험 중심 | 관계 변화·로맨스·감정선 중심 |
| `challenge` | 도전 지향 | 편안한 이야기·캐릭터성 중심 | 전투·추리·자원 관리 등 난도 있는 플레이 선호 |

레이더는 취향의 **모양**을 보여 주는 도구입니다. 두 사람의 모양이 겹친다고 자동으로 안전하거나 즐거운 세션이 되는 것은 아니며, 환경과 경계 조건을 먼저 확인합니다.

### 별도 조율 항목

아래는 하나의 숫자로 뭉개지지 않도록 카드/선택지로 결과에 남깁니다.

- 환경: 온라인·오프라인, 보이스·텍스트, 선호 플랫폼, 1:1·소규모·다인, GM/PL 희망
- 운영: 가능한 시간대, 사전 조율 리드타임, 세션 길이·휴식, 지각·불참 연락 기준
- 소통: 사담 채널, 메타 발언, 밈/초성, 세션 중 멀티태스킹의 허용 범위
- 플레이: 은닉·정보 격차, 레일로드, 캐릭터 조종, 로스트, PVP, 캐릭터 간/NPC 로맨스
- 콘텐츠 경계: 각 소재별 `ok` / `ask` / `no` 및 수위 선호. `ask`는 동의 완료가 아니라 대화가 필요하다는 뜻입니다.

## 결과 JSON 초안

개인 식별 정보는 기본적으로 저장하지 않습니다. 닉네임은 비교 화면에서만 쓰는 선택 항목이며, 내보내기 전에 수정하거나 비워 둘 수 있습니다.

```json
{
  "schemaVersion": "1.0",
  "displayName": "달빛 주사위",
  "role": ["PL"],
  "radar": {
    "pace": 72,
    "expression": 61,
    "immersion": 80,
    "structure": 44,
    "cooperation": 86,
    "conflict": 35,
    "relationship": 68,
    "challenge": 57
  },
  "session": {
    "formats": ["online", "text"],
    "groupSizes": ["2-4"],
    "platforms": ["cocofolia", "discord"],
    "leadTime": "weeks",
    "maxHours": 5
  },
  "preferences": {
    "oocChat": "ok",
    "metagame": "ask",
    "pvp": "ask",
    "romancePc": "ask",
    "romanceNpc": "ok",
    "characterControl": "no",
    "characterLoss": "ask"
  },
  "boundaries": {
    "violence": "ok",
    "gore": "ask",
    "sexualContent": "no",
    "discrimination": "ask"
  },
  "createdAt": "2026-10-06"
}
```

`ok`, `ask`, `no`는 각각 허용, 사전 협의 필요, 불가를 뜻합니다. 실제 서비스에서는 `schemaVersion`별 검증을 하고, 알 수 없는 키는 보존하되 비교 계산에서는 제외합니다.

## 적합도 계산

### 1. 먼저 통과해야 하는 조건

다음은 퍼센트 계산 전에 별도로 보여 줍니다.

1. 공통 세션 형식·인원·플랫폼·시간대가 없으면 `일정/환경 미매칭`입니다.
2. 어느 한 사람이 `no`로 설정한 항목을 다른 사람이 원하거나 세션에 포함하려 하면 `진행 불가`입니다.
3. 한쪽 또는 모두가 `ask`인 항목은 `사전 합의 필요`입니다. 합의 전에는 적합도에 포함하지 않습니다.

경계 항목을 평균 점수로 상쇄하지 않습니다. 예를 들어 95%라는 레이더 유사도가 있어도 콘텐츠 경계가 충돌하면 세션 추천 결과는 “조율 필요”가 됩니다.

### 2. 두 사람의 레이더 유사도

각 축의 차이를 `d_i = |a_i - b_i| / 100`으로 두고, 축 가중치 `w_i`의 합이 1일 때:

```text
radarSimilarity = 100 × (1 - Σ(w_i × d_i))
```

초기 버전은 모든 축을 같은 가중치(`1/8`)로 둡니다. 비교 화면에서 참가자가 중요 축을 조절할 수 있게 하되, 기본값과 변경된 가중치를 함께 표시합니다. 이는 “같은 취향일수록 편하게 시작하기 쉽다”는 지표일 뿐, 보완적인 조합의 가치를 부정하지 않습니다.

### 3. n명 그룹 적합도

`n ≥ 2`일 때 모든 참가자 쌍의 `radarSimilarity` 평균을 **그룹 레이더 적합도**로 표시합니다. 함께 다음 값도 제공해야 평균이 약한 조합을 가리지 않습니다.

- 최저 쌍 점수와 해당 두 사람
- 쌍별 점수 행렬(히트맵)
- 각 축의 최대 편차와 가장 다른 두 사람
- 환경/경계 미매칭 및 사전 합의가 필요한 항목

최종 표기는 `레이더 유사도 78% · 조율 필요 2건`처럼 분리합니다. “전체적으로 잘 맞는다”는 단일 판정은 제공하지 않습니다.

## 비교 화면 UX

1. 각자가 결과 JSON 파일을 내려받거나 붙여 넣습니다.
2. 비교 화면에서 2명 이상을 드래그 앤 드롭해 불러옵니다. JSON은 브라우저 안에서만 파싱하며 서버 업로드를 기본값으로 하지 않습니다.
3. 참가자별 색과 이름을 선택하고, 8축 레이더 다각형을 반투명하게 겹쳐 봅니다. 색각 이상을 고려해 색 외에 점선/실선과 범례를 사용합니다.
4. 아래에 쌍별 히트맵, 최저 편차 축, 공통 환경, 조율 카드(`ask`)를 차례로 보여 줍니다.
5. 필요한 경우 “비교용 요약 JSON”만 다시 내보냅니다.

참가자가 많아져 레이더가 읽기 어려워지는 `6명 이상`에서는 전체 겹침 대신 평균 다각형과 축별 범위(최솟값~최댓값)를 기본으로 하고, 특정 참가자만 선택해 겹쳐 볼 수 있게 합니다.

## 질문 설계 원칙

- 한 질문은 한 상황만 묻고, 선호하지 않음과 불가를 구분합니다.
- “항상”, “절대” 같은 단어 대신 세션 0에서 합의 가능한 구체적 상황을 제시합니다.
- 레이더 축당 3~4문항으로 시작하고, 역문항을 섞어 무조건 한 방향으로 답하는 편향을 줄입니다.
- 민감 콘텐츠 질문에는 `답변하지 않음`을 제공하며, 이는 `ask`보다도 비교에서 제외되는 비공개 상태입니다.
- 결과 페이지에는 점수 설명과 함께 실제 조율 질문을 제안합니다. 예: “PVP가 가능한 범위는 어디까지인가요?”, “메타 발언은 어느 채널에서 할까요?”

## 범위와 다음 단계
